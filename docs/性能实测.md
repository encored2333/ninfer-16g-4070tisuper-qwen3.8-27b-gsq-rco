# 性能实测：RTX 4070 Ti SUPER (16GB) · Qwen3.8-27B GSQ-RCO IQ3_S

> 测试时间 2026-10-01 · 引擎为源码构建 sm_89 版 · strict 显存驻留 · KV 97,280 tok (rk8v4) ·
> MTP×4 自适应 + ngram 31 · 测速口径与官方一致（引擎 timings 字段）
>
> 对照参考：RTX 5070 Ti 16GB 官方实测（docs/rtx-5070ti-windows.md，2026-09，S 档 IQ3_S）
> 两卡带宽：672 GB/s vs 896 GB/s（比值 0.75）

## 与 RTX 5070 Ti 官方 64K 档对比

| 指标 | 5070 Ti 参考 | 4070 Ti SUPER 实测 | 实测/参考 | 75% 带宽折算预期 |

## 分析

1. **Decode 反超参考卡（109%）**：看似违反带宽比，实际合理——参考值是满 64K 输入下的解码，
   本机该档只喂了 51.8K（KV 更短、注意力更便宜），且 MTP 自适应草稿的接受率随内容波动。
   与官方"页面生成案例 123.6 tok/s"的短上下文口径对齐看，本机专项 139.7 同样领先。
2. **Prefill 86%**：高于 0.75 的带宽比；prefill 对算力密度更敏感，4070 TiS 的 Ada 架构在
   INT8/FP16 张量吞吐上对 Blackwell 的比值优于纯带宽比。
3. **长输入衰减温和**：3.3K→51.8K prefill 仅降 12.6%（1,665→1,455），KV 池 rk8v4 压缩与
   分块流水工作正常。
4. **TTFT 持平**：52K 输入 35.7s vs 官方 36.9s，strict 驻留没有带来额外惩罚。

## 视觉版附加实测（2026-10-01）

视觉制品（text,mtp,vision，1176 张量）· `--vision-residency cpu` · default 策略 · 48K 上下文：

| 项 | 值 |
|---|---|
| 测试输入 | 256×256 纯红 PNG（OpenAI `image_url` + base64 data URI） |
| 模型回答 | 「红色」✓ |
| prompt tokens | 130（图片合并约 76 个视觉 token） |
| 全程耗时 | 17.6 s（CPU 图片编码 + xhigh 思考 + 短输出） |
| KV 池 | 49,152 tok · runtime 2.66 GiB · free 1.49 GiB |

文本性能不受影响（视觉塔在 CPU）；图片编码在 CPU 上是主要延迟来源，换 `resident`（GPU 塔，
约 1GB 显存）可显著加快，代价是上下文再缩且失去 strict（视觉构建本就无法用 strict）。

## 复测方法

```bash
# 纯标准库实现，无需 pip；流式 SSE，TTFT 取首个非空事件，prefill/decode 取引擎 timings
py -3.11 scripts/validate/bench.py --base http://127.0.0.1:8081 --model qwen3.8-27b --mode quick
py -3.11 scripts/validate/bench.py --base http://127.0.0.1:8081 --model qwen3.8-27b --mode full

# 显存驻留监控（另一窗口）
powershell -File scripts/validate/watch_vram.ps1
```

64K 档的输入由固定句重复构造到目标 token 数，实际以服务端 `usage.prompt_tokens` 为准。
bench 结尾自动打印与 5070Ti 参考值的对比表。

## 通过标准（任何 40/30 系机器复现时）

- `/health` 200；短请求 `finish_reason=stop`、tokens>0
- strict 启动日志：`admitted N KV tokens` 且 `free > 100 MiB`
- 64K 档解码在 70–140 tok/s 量级；**掉到个位数 = 显存溢出 Shared 内存**（strict 会拒绝启动，
  不会静默掉速；若用 mixed 策略则会掉速，实测 4.65 tok/s，仅应急）
